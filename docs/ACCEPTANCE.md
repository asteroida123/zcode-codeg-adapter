# 验收：区分启动层、真实桥接包、真实 ZCode/Codeg

## 自动测试

- npm run check：JavaScript 语法。
- npm test：启动层和模拟上游测试；包括环境清理、版本固定、stdout 原样传递、错误脱敏、启动一次、cwd/进程身份不变、POSIX 信号。
- npm run test:upstream：真实 npm 上游包，在隔离 HOME 中 initialize → 未知方法的 -32601 → EOF / POSIX SIGTERM 退出。没有安装 ZCode，没有发 session/prompt，不测试模型或文件工具。Windows 不模拟 POSIX SIGTERM。

缺少上游依赖必须失败，不可以 skip 后宣称兼容。没有安装锁文件时安装得到的传递依赖可能变动；首次通过后保存真实生成的 package-lock.json。常规安装改用 npm ci --ignore-scripts。

## 真实机器的手工验收（均未由无凭据 CI 代替）

记录：OS/架构、Node 版本、Codeg 版本或 commit、ZCode 桌面及 CLI 版本、适配器 commit、上游版本。先用一次性测试工作区，不用生产仓库。

| 场景 | 验收要求 |
| --- | --- |
| 登录/连接 | 已在官方 ZCode 登录；Codeg 创建新会话，模型/权限选项可正确读取。doctor 成功不等于此项成功。 |
| 流式回答 | 提问“只回复 OK”；真实收到逐步输出与正常回合结束。 |
| 文件修改 | 明确要求在临时工作区新建测试文件；Codeg 呈现工具轨迹和改动，实际文件正确。 |
| 拒绝权限 | 使用需要确认的模式，拒绝一次敏感操作；检查该操作实际未执行，不仅是 UI 消失。不要启用 yolo。 |
| 取消 | 长响应中点击停止；确认后端停止，随后新 prompt 不被旧回合污染。 |
| 等待授权时取消 | 在权限弹窗等待期间停止/关闭会话，确认无悬挂授权、无迟到批准。 |
| 恢复 | 关闭并重启 Codeg，再打开并续问；历史、sessionId 与后端恢复一致，无空白/重复/串话。 |
| 多会话/工作区 | 两个项目分别创建会话；cwd、模型配置、工具权限、文件操作与消息互不串用。 |
| MCP/委派 | Codeg 开启 delegation，确认 companion 被接收；主/子会话的工具调用和结果可见。 |
| 退出/异常 | 关闭 Codeg 或终止适配器，检查真实 ZCode 后端进程是否退出；Windows 单独验证，不能以 POSIX 测试替代。 |
| 隐私/配置 | 检查适配器不打印凭据、不启动远程监听；分别审查上游及 ZCode 日志/网络行为。 |

失败应定位在 Codeg、薄启动层、上游桥接、ZCode 四层之一。上游协议故障优先最小复现并反馈上游，不能把整段翻译器复制过来打补丁。
